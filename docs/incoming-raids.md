# 随机来袭军队

只提供外部调用接口，不注册 cron、不创建周期生成器、不自动生成敌军。你自己的调度服务决定何时调用。

## 入口

- 执行：`GET /api/admin/tasks/spawn-incoming-army/run`，每次生成一支。
- 地址清单：`/admin#tasks`，提供完整地址、复制、说明及最近成功结果。
- 规则配置：`/admin#controls` → 来袭军队；读取/保存分别为 `GET` / `PUT /api/admin/incoming-army`。
- 前台各页面顶部显示来袭军情、攻击方向、战力、人数和倒计时。

部署到 110 后的执行地址：

```text
http://192.168.3.110:5173/api/admin/tasks/spawn-incoming-army/run
```

此 URL 有副作用，勿作为普通网页链接打开或预览。复用既有 GET 调度的可选令牌、防预取、参数校验和重试去重。建议每轮附加唯一 `?requestId=本轮编号`，超时重试沿用该编号；不传编号则每次都生成。去重仅覆盖该任务最近50条成功记录，不同调度周期不可复用编号。

## 默认配置

攻击范围 10,000～100,000，近攻、远攻、混攻随机。人数为总攻击力除以100向上取整，仅用于敌军伤亡展示，不再对总攻击重复乘人数或科技。每支出发后300游戏秒抵达；正常倍率即5分钟，加速、跳时和暂停沿用现有游戏时钟。

每种合格物品独立25%概率掉落，默认数量如下：

| 类别 | 每种数量 |
| --- | --- |
| 装备、宝物 | 1～2 |
| 技能书 | 2～5 |
| 消耗品 | 5～20 |
| 各系一级宝石 | 100～1,000 |
| 材料 | 10～50 |

上述范围、概率、数量和开启状态均可在后台修改。攻击范围允许1～100亿，单种物品数量1～10,000。每种物品分别随机，没有必掉保证；掉率设100%即所有合格物品都掉落。

生成时固化攻击和掉落参数，后改配置只影响新敌军；关掉生成不会取消已经出发的敌军。待结算最多100支，达到上限会拒绝新增且事务回滚。刷新任何地图目标不会附带生成敌军。

## 守城和伤亡

抵达时使用已完成营造的城防、留城士兵的近远防，按当前满科技计算。攻击方向决定取近防、远防或按敌方近远攻占比加权，不简单把双防相加。英雄、在途部队、自动出征预留编队及尚未完成的训练不参加本轮守城。

按游戏时间顺序补结算：先返城再遇袭的普通部队可以守城；晚于来袭的返城不提前计入。同一时刻普通返城先于来袭。关闭浏览器继续结算；停服后下次启动补算，不需要为“到达”另配调用地址。

- 弱方全灭；战力相等则平局、双方全灭。
- 强方总损失＝`floor(强方总人数 × (弱方战力 / 强方战力)²)`。
- 总损失按各兵种／城防的数量比例分配余数，不因拆成多个兵种而免除损失。

双方每人战力相同的示例：100对100双方全灭；100对1,000，强方损失10；100对10,000，强方损失1；100对100,000，强方零损失。

只有守方战力更高、防守胜利才发放物品。平局、失败没有奖励；不额外扣仓库资源。胜利遍历当前已上架、未删除的物品，技能书还要求对应技能上架；宝石仅各系一级，不发二至八级或旧无等级宝石。按实际结果直接入包，技能书记入技能书库存。

## 战报与存档

战报列表在“胜利”后直接展示掉落名称和数量，仍然点击原条目展开详情。被攻击页显示我军城防与兵力损失、敌军损失、实际战利品，被攻击记录永久保留；清空／自动裁剪仅处理主动战报。

新增 `incoming_raids` 只保存待结算军队。结算中的扣兵、奖励、写战报和删除待办属于同一事务；失败整体回滚，重复处理不重复扣兵或发奖。已完成来袭不再占待办表，通过永久战报查询。

完整结构及 JSON 字段设计在 `database/schema.sql`，增量为 `database/migrations/0022_incoming_raids.sql`。已有存档运行 `npm run db:update`（或单独 `npm run db:update:incoming-raids`）；`bash deploy.sh` 自动纳入此更新，不需要额外输入数据库参数。迁移只添加结构和默认规则，不生成敌军、不重置兵力或背包；重复运行保留后台自定义值。未升级时旧游戏可以读取世界状态，来袭接口会拒绝执行。

本次仅测试和推送代码，没有部署110、持久升级数据库或生成真实来袭。以上是实现和部署后行为，不代表服务器已运行新版。
