# 兵种、编队与城防生产（2026-09-17）

## 本轮范围

前台 `/` 增加“军营”；“天下”提供英雄头像与兵种数量编队，可纯士兵出征；“城防”改为生产队列。后台 `/admin#military` 统一编辑名称、说明、四项攻防、速度、负重、五项资源价格、单单位耗时、启用状态。前台轮询同步，不需要重启。

启用9个作战／运输兵种：粮草兵、运输车、枪盾兵、强弩兵、长枪兵、弓箭兵、骑枪战将、骑射战将、重甲将军。侦察兵、拓荒部队需对应侦察／开城玩法，本轮未用普通攻击冒充。用户后续确认按查到的资料实现，未考证的“双攻高速金币骑兵”不纳入启用目录；本轮开发期间产生的占位定义只停用，不删除已有资产。

## 结算规则

- 单位拥有独立近攻、远攻、近防、远防、移动速度和负重。满科技沿用项目既有+100%适配；技能与科技相加，单兵种技能随机选择一个符合通道的兵种。
- 总攻击为近攻+远攻；有效防御为`近防×近攻占比 + 远防×远攻占比`。防御属性不作为出征攻击。
- NPC系统城／随机城将防御分为驻军65%、工事35%；破城技能只针对工事。该比例及NPC分配为单机适配。自己的城防与驻城士兵已计算双防总量；没有新增虚拟玩家自动来袭，因此当前尚无完整真实守城遭遇流程。战斗内核支持防方部队、城防和技能，不等同于已经开放NPC攻城。
- 行军使用最慢的存活单位速度，地图距离换算沿用项目的单机公式；出发时记录部队属性快照，后台修改不会追改在途士兵。英雄属性与技能在战斗时读取，出征期间不可培养修改。
- 派兵立即从可用库存扣除。抵达结算技能、资源负重和逐兵种损失；只有幸存者返城后回到城内。掉落仍使用现有掉落池；所有可攻击目标每战降一级，失败也生效，0级消失。
- 伤亡暂用独立比例曲线`min(1,(对方战力/本方战力)^1.5)`，再应用减伤技能、确定性随机取整。此曲线不是已考证原版算法。英雄不因普通士兵阵亡被删除。
- 新自动编队会实际往返，不瞬时刷取；兵力由任务或在途行军二者之一持有，不能被另一队重复派遣。暂停只停止后续出征，已经在途的队伍正常战斗、返城；纯士兵全灭或目标耗尽时结束。
- 新派遣先在同一事务内按时间顺序补结算到点的出发、战斗和返城，再检查所选英雄是否忙碌。第一位英雄刚开启自动刷野，不会再拦截第二位英雄的普通或自动派遣；已到点返城的英雄也会先释放占用。尚未到点的行军不提前结算，同一英雄仍不能重复出征。
- 补结算与扣兵共用玩家行锁和数据库连接，后台结算可安全交替执行；失败整体回滚，不丢兵、不重复发兵或生成战报。单次操作最多补结算200个事件，只有仍存在更多离线积压时才提示等待后台追赶。没有变更数据库结构。

## 生产时间与存储

- 军营和城防各一条独立队列，同一队列串行。提交时支付整批资源，生产逐个完成；刚下单数量不增加，未完工城防不提供防御。
- 队列由服务端游戏时钟结算，关浏览器不停止。停服务器后，下次启动补算到期单位；管理员倍率、跳时同样作用于队列及行军。
- 单次1至100000单位，每类最多50个未完成订单，总排队不超过一年游戏时间。更改配置只影响新订单；已付费队列使用原始耗时，避免丢单或追改成本。
- 生产订单完成后从前台队列移除；数据库保留7个现实日的微型重试凭据，然后定时结算时清理。普通行军返城后物理删除；自动出征任务按原要求保留。主动战报最多50条，被攻击记录永久保留。
- 新表`military_definitions`、`player_forces`、`military_orders`；新增行军请求编号、关联自动任务及自动任务兵力快照字段。完整无业务数据结构已同步`database/schema.sql`。
- 更新命令`npm run db:update:military`，只连接`fenghuo`；0010创建结构并迁移旧城防可用数量，0011停用未考证单位及撤销未证实附加费。老`city_defenses`只作为迁移档案保留，游戏以`player_forces`为准。不会重置英雄、装备或钱包。

## 接口

- `GET /api/military`：定义、可用库存、生产队列和驻城双防。
- `POST /api/military/orders`：`code,quantity,clientActionId`，入生产队列；同编号七日内重试不重复扣费。
- `POST /api/world/marches`：`heroId`可为空，`nodeId,troops:[{code,quantity}],clientActionId`；在途期间同编号不重复发兵。
- `POST /api/world/auto-farm`：英雄可为空，兵种编队、目标类别、等级范围、次数；暂停沿用原接口。
- `GET /api/admin/military`与`PUT /api/admin/military/:code`：管理定义。只在受信内网使用，不新增登录系统。
- 原`POST /api/city/defenses/build`兼容保留，但现在入队等待，不再即时建成。外部定时刷新GET接口保持不变。

## 管理员添加资源与军粮

`/admin#controls`顶部“添加资源”支持粮食、木材、石料、铁矿、金币、点券。每项输入本次增量，0表示不增加；可快捷填入10万或四项基础资源各100万，点击“添加资源”直接入库，填写数值或快捷填入本身不提交。每项每次最多十亿，余额安全上限九万亿，拒绝负数及小数，不覆盖原有余额。

`POST /api/admin/resources/grant`接收`{clientActionId,amounts:{food,wood,stone,iron,gold,coupon}}`，未填的项目按0。七日内同一编号和同一增量重试不重复发放；修改增量重用编号会拒绝。所有增量和操作后余额保存在`admin_resource_grants`，前台后台余额同步，最近20条可在表单下查看，七现实日后物理清理。`GET /api/admin/resources`读取当前余额和这些记录。

军粮以旧资料表的消耗量配置：粮草兵1、运输车3、枪盾兵／强弩兵2、长枪兵／弓箭兵4、骑枪战将／骑射战将12、重甲将军50，每名每游戏小时。旧版按小时耗粮另见[2010年野外驻扎玩家稿](https://web.17173.com/content/2010-10-07/1286465655.shtml)。城防、英雄与训练中未完成单位不收本轮士兵军粮。全军耗粮和现粮可支撑时长显示于游戏导航下，后台可修改单兵耗粮值。

驻城、行军、自动编队的士兵都计入，同一批士兵只计算一次；每个新兵从实际完成时刻开始，服务端按游戏时间连续扣除。单位耗粮参数对全军同步生效，改参数之前先结算旧值。小数余量保留，不因2秒一次结算而漏计。离线事件按出发、战斗、返城的发生时序追赶，死去的士兵不继续收费。军粮迁移从当前游戏时间锚定，不追收迁移前的军粮。

**缺粮只提示，绝不自动损兵或取消行军，不记欠款。补粮之前先结清旧区间（最低扣到0），补粮后从新时间继续扣，缺粮期间不追债。** 涉及兵力和粮食的操作会先补结算到点战斗，防止将新补粮拿去支付过去的缺粮；只有超过单次补结算上限的长时间离线积压才提示稍后重试。

此版本从统一城库持续扣行军军粮，没有复刻原版“出发先携带路粮”机制，属于单机简化，不声称完全一致。

升级使用`npm run db:update:resources`、`npm run db:update:upkeep`，或总命令`npm run db:update`。0012增加管理员资源凭据表，0013增加`military_upkeep`结算锚点、小数余量及`foodPerHour`配置；完整设计同步于`database/schema.sql`。
