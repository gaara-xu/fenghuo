# 无效道具清理

维护命令：`npm run db:cleanup:obsolete`。只连接 `fenghuo`，只清理 `.env` 指定玩家的包裹，不在普通启动或完整数据库更新时自动删除库存。

本次范围为原始无等级的近攻、远攻、近防、远防、速度、负重宝石（六个 `gem_属性名` 旧编号），以及用途尚未实现的 `synthesis_stone` 合成神石。旧宝石已由五系八级宝石替代，不支持现在的升级合成；曾有旧库存和首领历史掉落残留。

- 精确匹配旧编号、类别和原始配置；旧编号若已被后台改成有系别/等级或不同属性的宝石，则跳过。
- 正常40种宝石、精炼石、高级精炼石、精炼神石、天工神石、经验书、天赋水、体力药、改名卡及装备宝物不清理。不会把暂时停用或没有图标的物品一概当作废物。
- 执行前锁定玩家和相关数据，发现仍有目标宝石镶嵌在装备上便整体中止，不修改孔位、宝石快照或装备属性。
- 删除目标库存行，并停用物品定义、掉落条目和酒馆条目。物品定义和历史外键保留，不物理删目录。停用后普通掉落、首领与新酒馆刷新均不会产出。
- 酒馆中仍保存的废弃道具旧候选会隐藏，直接重试领取也会拦截；正常物品的已付费候选仍按原规则保留。
- 重复执行没有新库存或启用来源时不再写审计。出错全部回滚。

每个清理目标都有一条 `admin_audit_logs.action=CLEAN_OBSOLETE_ITEMS` 审计。`before_json` 保存玩家编号、原物品定义、完整库存行及两种来源条目，`after_json` 保存删除数量和原因；命令输出审计编号。如需恢复，应按审计编号还原对应库存及启用状态，先核对后续是否已获得新库存，避免覆盖后来进度。没有自动过期清理这些恢复记录。

完整结构及JSON约定同步在 `database/schema.sql`，本次无需新增表字段。
