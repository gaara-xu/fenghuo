# 酒馆藏宝阁

前台入口：酒馆 → 藏宝阁·珍宝。原顶栏“藏宝阁”仍是装备与宝物图鉴。

- 默认 8,000 金刷新 3 个候选，任选 1 件，不额外收取领取费用。
- 装备、宝物、消耗品、材料均来自统一物品库；技能书继续使用独立藏书阁。
- 每个候选独立加权抽取，可重复，无保底。默认每件白／蓝／黄／绿／蓝紫／橙黄／红物品的权重分别为 600／400／250／120／45／10／1；这些是单机配置，不是官方原始概率。
- 领取一件进入真实包裹。装备首次穿戴后沿用独立实例、精炼与打孔系统。重复请求不会重复扣金或发物品，英雄数量上限不限制物品领取。
- 悬停物品图标或用 Tab 聚焦图标可直接查看品质、说明、属性与套装效果；离开图标立即收起，移到说明上也不会保留。鼠标留在图标上用滚轮翻阅，键盘可用 PageUp／PageDown；Esc 收起。
- 每个分页分别恢复最近一次刷新，关闭浏览器不重置。再次刷新会在界面中替换当前分页的候选，不会自动领取未选物品。

## 后台管理

`/admin` → 城主控制台 → **酒馆刷新记录**：统一控制聚贤馆、藏书阁、藏宝阁。当前已关闭。

- 关闭：刷新结果、候选快照、随机种子、请求编号均不写数据库，也不输出刷新／领取的应用访问及错误日志。只更新正常扣费余额与实际领取的英雄、技能书、物品。
- 每个卡池在游戏服务内存中只保留当前一轮，另保留至多 512 个请求编号用于本次进程内去重，不写文件。
- 切换开关不删除表和历史，保留当时已付费的当前候选，并阻止旧数据库候选重新领取。开关本身保存在 `game_settings.tavern_recording`，服务重启后仍保持关闭。
- 浏览器刷新、关闭、切换分页不影响当前候选。**关闭或重启游戏服务会清空内存候选，已扣刷新费用不退；已领取奖励不丢失。** 网络中断时可重试，但不提供跨服务重启的刷新幂等保证。
- 再次开启：从之后的新刷新开始入库；当前内存轮次仍只在当前进程有效，不补写历史。原有库表与旧历史始终保留。
- 内存模式仅支持一个后端进程；不要在多个 Node 进程／容器之间轮询，否则各进程候选不共享。
- 只控制游戏应用自身记录，不修改 MySQL 服务审计、服务器系统日志或将来的 Nginx 访问日志。

设置接口：`GET /api/admin/tavern-recording` 返回 `{enabled:boolean}`；`PUT` 提交同一结构更新，不是外部定时任务。

`/admin` → 城主控制台 → 酒馆卡池，选择“藏宝阁·珍宝”。

- 添加或停用入池物品、修改权重，查看单个候选位概率。
- 修改每次费用、候选数量（1–6）、可选数量（不超过候选数）；从下一轮生效。
- 物品与培养页面统一增改物品；新物品需手动加入卡池。停用或回收的物品立即停止参与之后的抽取。
- 已付费候选保留名称、图标、说明、品质快照和本轮可选数量；之后即使停用／回收，仍可领取。入包后属性和可用状态跟随统一物品定义，恢复定义后可继续使用。

## 数据库与升级

完整结构仍以 `database/schema.sql` 为准，不含业务数据。新增 `0014_tavern_treasure` 迁移包括 ITEM 奖励、物品外键与快照、每轮选取上限快照；已有英雄与技能书候选保留。

已有存档运行 `npm run db:update:tavern`，会先补齐回收站依赖；完整更新链 `npm run db:update` 也包含本次更新。可重复执行，不覆盖已调整的权重、费用或玩家库存，不需要重跑种子。

测试覆盖空池／缺钱不扣费、四类入包、重试防重、类型检查、停用回收排除、快照、各分页恢复、后台与前台 HTTP。实库测试仅操作 fenghuo，业务写入最终全部回滚。
