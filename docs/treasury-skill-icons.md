# 藏宝阁与图标选择界面

## 游戏前台

- 顶部新增“藏宝阁”：装备与宝物在同一个图标网格中混排，按品质从高到低排列。
- 搜索名称或说明、按七档品质筛选、仅看已拥有。图标角标为包裹数量与穿戴数量之和。
- 悬停显示说明，点击显示属性、实力要求、套装效果、包裹／穿戴数量。
- 从只读接口 `GET /api/catalog/items` 获取目录，不使用一份独立的硬编码图鉴。可见时每 2 秒更新，切回窗口时更新，也可手动刷新；失败保留当前目录，不刷屏。
- “我的物品”仍为实际库存。英雄详情的技能书、装备、两个宝物槽、精炼／打孔／镶嵌材料均使用包裹式图标选择器，不再使用下拉框。
- 点击图标只选中；学习、替换、装备与培养仍要点击对应操作按钮。不同实例保留独立编号、精炼与宝石状态，出征期间不可操作。

## 技能图像

本轮获准复制清单内 37 张已生成原图，源文件保留不变。与项目已有 7 张合并，共 44 个独立技能图标。

- 原图副本：`public/art/skills/originals/`（仅本轮 37 张）。
- 小图：`public/art/skills/<key>-small.png`，64 × 64。
- 大图：`public/art/skills/<key>-large.png`，256 × 256。
- 导入记录及 SHA-256：`public/art/skills-generation-20260916.json`。
- 导入脚本：`scripts/import-skill-art.ts`，只按该清单复制精确文件，不枚举外部目录，不改动源文件。重复运行校验已导入副本，不覆盖现有图。
- 酒馆、技能图鉴、英雄技能槽、包裹及后台使用统一映射；选择详情加载大图。

## 后台共用目录与回收站

`/admin` → 物品管理 → 物品目录，新增、修改、停用内容会同步影响藏宝阁。技能书仍由技能管理维护。

装备和宝物的删除为可恢复的软删除：

- `DELETE /api/admin/items/:id` 移入回收站。
- `POST /api/admin/items/:id/restore` 恢复原启用状态。
- 藏宝阁隐藏，停止新掉落、新穿戴和继续培养。
- 不删除物品定义、库存、穿戴关系、精炼、孔位或宝石；已穿戴属性保留，可正常卸下。恢复后可以继续使用。
- 删除／恢复记录写入审计日志；重复请求不重复记录。已删除定义不能直接修改，需先恢复。

## 数据库升级

新增 `item_definitions.deleted_at`，已同步完整无数据结构文件 `database/schema.sql` 与迁移 `0009_treasury_catalog.sql`。

在游戏目录执行：

```sh
npm run db:update:treasury
```

脚本只连接 `fenghuo`，先验证库名，使用更新锁并检查字段是否存在。不会修改或重置现有物品数据。完整 `npm run db:update` 也包含此步骤。

本轮自动执行因工具审批额度限制未能运行，实库迁移尚待完成。旧结构可以继续使用游戏、图标选择和藏宝阁读取；点击删除／恢复会提示先更新数据库，不会部分修改数据。迁移完成后无需重启开发服务。
